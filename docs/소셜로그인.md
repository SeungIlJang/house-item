# 소셜 로그인 (구글 · 카카오)

이메일/비밀번호 로그인은 제거했고, 구글과 카카오만 지원합니다.

## 왜 이 구조인가

- 구글은 임베디드 WebView 에서의 OAuth 를 차단합니다(`disallowed_useragent`).
  그래서 네이티브에서는 **시스템 브라우저(Custom Tabs)** 로 열어야 합니다.
- 카카오 REST API 앱의 Redirect URI 는 **https** 주소여야 합니다.
- `client_secret` 을 앱에 넣을 수 없으므로 **코드 교환은 Worker 에서** 합니다.

```
앱  ── Browser.open ──▶  GET /api/v1/auth/<provider>/start   (Worker)
                              │  302
                              ▼
                         구글 / 카카오 동의 화면
                              │  code
                              ▼
                         GET /api/v1/auth/<provider>/callback (Worker)
                              │  토큰 교환 → 사용자 조회·생성 → 자체 JWT
                              ▼
앱  ◀── appUrlOpen ──  com.homeitems.app://auth?token=...
```

## 데이터 모델

`0002_social_auth.sql` 에서 변경했습니다.

- `users.email`, `users.password_hash` 를 **선택값**으로 변경
  (카카오는 이메일 동의항목이 심사 대상이라 못 받을 수 있음)
- `auth_identities(provider, provider_user_id)` 로 실제 식별
- `oauth_states` 에 state 와 PKCE `code_verifier` 를 10분간 보관, 콜백에서 1회 사용 후 삭제

같은 이메일을 주는 제공자끼리는 기존 계정에 자동 연결됩니다.

## 1. 구글 설정

Google Cloud Console → API 및 서비스 → 사용자 인증 정보

1. **OAuth 동의 화면** 구성 (외부, 앱 이름, 지원 이메일, 개인정보처리방침 URL)
2. **사용자 인증 정보 → OAuth 클라이언트 ID → 웹 애플리케이션**
3. 승인된 리디렉션 URI 에 추가:
   `https://<워커도메인>/api/v1/auth/google/callback`
4. 클라이언트 ID / 보안 비밀번호를 받아둡니다.

> 네이티브 SDK 를 쓰지 않으므로 Android 클라이언트(SHA-1)는 필요 없습니다.

## 2. 카카오 설정

[developers.kakao.com](https://developers.kakao.com) → 내 애플리케이션

1. 앱 생성 → **앱 키**에서 `REST API 키` 확인
2. **카카오 로그인** 활성화 ON
3. **Redirect URI** 등록: `https://<워커도메인>/api/v1/auth/kakao/callback`
4. **보안 → Client Secret** 발급 후 "사용함" 으로 설정
5. **동의항목**: `닉네임`(필수), `프로필 사진`(선택) 만 켭니다.

> ⚠️ 이메일은 개인정보 동의항목이라 **심사(영업일 3~5일)** 가 필요합니다.
> 현재 코드는 이메일이 없어도 동작하므로, 처음에는 신청하지 않는 편이 빠릅니다.
> 나중에 받게 되면 자동으로 `users.email` 에 저장됩니다.

## 3. Worker 시크릿 등록

```bash
cd worker
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put KAKAO_REST_API_KEY
npx wrangler secret put KAKAO_CLIENT_SECRET
npx wrangler secret put JWT_SECRET_KEY        # 아직 없다면
```

`APP_REDIRECT_URI` 는 비밀이 아니므로 `wrangler.jsonc` 의 `vars` 에 둡니다.

```jsonc
"vars": {
  "APP_REDIRECT_URI": "com.homeitems.app://auth"
}
```

## 4. 마이그레이션 · 배포

```bash
cd worker
npx wrangler d1 migrations apply home-items-db --remote
npx wrangler deploy
```

## 5. 안드로이드 딥링크

`android/` 는 `npx cap add android` 로 생성되는 디렉터리라 저장소에 없습니다.
생성 후 `android/app/src/main/AndroidManifest.xml` 의 **MainActivity** 안에
아래 인텐트 필터를 추가하세요. (기존 `android.intent.action.MAIN` 필터는 그대로 둡니다)

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="com.homeitems.app" android:host="auth" />
</intent-filter>
```

그다음:

```bash
cd home-items-app
npm install          # @capacitor/browser 설치
npm run build
npx cap sync android
```

## 확인 방법

1. 로그인 화면에서 [Google로 계속하기] → 시스템 브라우저가 뜨는지
2. 동의 후 앱으로 돌아와 홈 화면으로 이동하는지
3. 브라우저를 그냥 닫으면 조용히 로그인 화면에 머무는지(취소 처리)
4. 같은 계정으로 재로그인 시 **새 사용자가 생기지 않는지**
   (`auth_identities` 에 같은 `provider_user_id` 가 1건이어야 함)

```bash
npx wrangler d1 execute home-items-db --remote \
  --command "SELECT u.id, u.name, u.email, a.provider FROM users u JOIN auth_identities a ON a.user_id = u.id"
```
